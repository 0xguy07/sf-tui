# `sftui perms` and the permissions refactor — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `sftui perms <user> [--object X]` prints per-permission sources (and Modify/View All Data overrides) as text or JSON, and the TUI's Perms tab uses the same code.

**Architecture:** Pure builders in `sf/` turn decoded `sf data query` records into a `PermissionsReport`. A `soqlRunner` interface is the only I/O seam; the TUI's `tea.Cmd`s and the CLI both call `BuildPermissionsReport`. The CLI reuses the `why` dispatcher, `splitPositional`, and exit-code conventions.

**Tech Stack:** Go 1.24, stdlib only.

**Spec:** `docs/superpowers/specs/2026-11-05-perms-cli-design.md`

## Global Constraints

- No new module dependencies.
- stdout carries data only; diagnostics to stderr. Exit codes `0` success incl. partial, `1` runtime, `2` usage.
- Read-only: `cliDeps` gains only `resolveUser` and `perms`; no new file references `gate`.
- Existing exported names and JSON tags on `ObjectPerm`, `FieldPerm`, `PermSetAssignment`, `PermissionsLoadedMsg`, `FieldPermissionsLoadedMsg` are kept; fields are only added.
- Source label format: permission set `Label`, or `Profile: <Profile.Name>` when `IsOwnedByProfile`.
- Text output has no ANSI. Tests touch no real org and no real config directory.
- `gofmt -l .` empty; `go vet ./...`, `go test ./...` pass.

## Review Focus

1. **A source that grants several permissions on one object** (Sales Ops grants Create and Edit on Account): it must appear once per permission in `grants` and once in `sources`. Test in Task 2.
2. **A user with no assignments at all** (possible for an inactive or Chatter Free user): valid empty report, text says `Assignments (0):`, exit 0. Test in Task 3.
3. **An ambiguous display name** ("Alex Admin" twice): exit 2, both candidates on stderr with username and Id. Test in Task 6.
4. **An org whose API rejects `PermissionSetGroup.MasterLabel`**: the assignments query is retried without the group columns and the report still succeeds. Test in Task 3.
5. **`--object` for an object with no FieldPermissions rows**: `Fields on X (0):` with the explanatory line, not an empty block or an error. Test in Task 5.

### Task 3: `BuildPermissionsReport` and `ResolveUser`

**Files:**
- Create: `sf/permissions_user.go`, `sf/permissions_report_test.go`

**Interfaces:**
- Consumes: builders from Tasks 1–2, `soqlRunner`.
- Produces:
  ```go
  type PermissionsReport struct {
      User        UserBrief           `json:"user"`
      Assignments []PermSetAssignment `json:"assignments"`
      Overrides   Overrides           `json:"overrides"`
      Objects     []ObjectPerm        `json:"objects"`
      Object      string              `json:"object,omitempty"`
      Fields      []FieldPerm         `json:"fields,omitempty"`
      Errors      []SectionError      `json:"errors"`
  }
  // UserBrief gets tags: id, name, username, isActive, profile (ProfileName → json:"profile")
  func BuildPermissionsReport(q soqlRunner, org string, user UserBrief, object string) (PermissionsReport, error)
  func ResolveUser(q soqlRunner, org, ident string) (UserBrief, error)
  type ErrAmbiguousUser struct{ Ident string; Candidates []UserBrief }   // Error() lists "<Name>  <Username>  <Id>" per line
  var ErrUserNotFound = errors.New("no user matches")
  const assignmentsSOQL, assignmentsSOQLNoGroup   // the two query forms from the spec
  ```
  `BuildPermissionsReport` returns a non-nil error only when the assignments query fails (after the no-group retry). Object-perms or field-perms failure → `Errors` entry, exit stays 0 at the CLI. The retry triggers when the first assignments query errors and the error text contains `PermissionSetGroup`.
  `ResolveUser`: Id when `len==15||18` and prefix `005`; username when contains `@`; else name. SOQL `WHERE Id = '…'` / `WHERE Username = '…'` / `WHERE Name = '…'` with `soqlEscape`. No `IsActive` filter.
