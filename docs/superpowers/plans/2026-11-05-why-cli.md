# Non-interactive `sftui why` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `sftui why <recordId>` prints the Why tab's investigation as plain text or JSON, with no TUI, usable in scripts and pipes.

**Architecture:** A small subcommand dispatcher in `package main` runs before the Bubble Tea program starts. The `why` command resolves the org, validates the Id, calls the existing `sf.BuildTrace`, and renders. All Salesforce access goes through an injectable `cliDeps` struct so tests run offline against fixtures.

**Tech Stack:** Go 1.24, stdlib `flag`, `encoding/json`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-05-why-cli-design.md`

## Global Constraints

- No new module dependencies.
- stdout carries data only; every diagnostic goes to stderr.
- Exit codes: `0` success (including partial results), `1` runtime failure, `2` usage error.
- The command is read-only: `cliDeps` exposes no write capability and nothing in the new files references `sf.Gate` or `gateWrite`.
- `sftui` with no arguments still starts the TUI unchanged.
- `--version` / `-v` / `version` are recognised only as the first argument.
- Text output has no ANSI escapes. Timestamps render in UTC as `2006-01-02 15:04:05 UTC` so goldens are stable across machines.
- Tests never touch the user's real config directory.
- `gofmt -l .` prints nothing; `go vet ./...` and `go test ./...` pass.

## Review Focus

1. **Id after flags or before them** (`sftui why 001… --org x` and `sftui why --org x 001…`): stdlib `flag` stops at the first positional, so both orders must work. Test in Task 5.
2. **Id with surrounding whitespace** (pasted from a browser): trimmed before validation, then accepted. Test in Task 5.
3. **`--format JSON` in upper case**: accepted case-insensitively. Test in Task 5.
4. **A record with no tracked field changes** (history tracking off): text output says so explicitly instead of printing an empty section. Test in Task 4.
5. **`sf` missing or org not authenticated**: the error from `sf.RESTFor` surfaces as exit 1 with the underlying message on stderr and nothing on stdout. Test in Task 5.

Layout (exact copy where fixed):
```
Why did <record.id> change?
Object: <object.label> (<object.name>)
Tracked fields: <comma-joined trackedFields, or "none">

Saves (newest first):

<at as 2006-01-02 15:04:05 UTC>  <user.name> [<badge>]   (no badge → omit brackets; nil user → createdById)
  <username> · UserType: <userType>[ · Profile: <p>][ · License: <l>][ · inactive]

    (no automation on this object writes this field)   (when Writers is empty)

(history truncated: only the most recent rows were loaded)   (only when historyTruncated)

Automation (order of execution):

<section.title>[ — <note>]
  [C][U][D] <item.Display()>[ · order N][ · inactive][ · writes F1, F2][ · updates a record variable][ · <detail>]

Errors:
  <section>: <message>                         (section omitted entirely when no errors)
```

### Task 5: The `why` command

**Files:**
- Create: `cli_why.go`
- Create: `cli_why_test.go`
- Modify: `cli.go` (replace the Task 1 stub with the real `runWhy`)

**Interfaces:**
- Consumes: `cliDeps`, `renderTraceText`, `sf.ValidRecordID`, `sf.ErrRecordNotFound`.
- Produces:
  ```go
  func runWhy(args []string, stdout, stderr io.Writer, d cliDeps) int
  func splitPositional(args []string) (id string, rest []string)  // first non-flag arg is the Id; the rest go to flag.Parse
  ```
  Flags: `--org`/`-o` string, `--format` string default `text`, `--refresh` bool. `flag.NewFlagSet("why", flag.ContinueOnError)` with output set to `stderr`.

Behaviour, in order:
1. `splitPositional`, parse flags. Parse error → exit 2.
2. `id = strings.TrimSpace(id)`; empty → usage, exit 2; `!sf.ValidRecordID(id)` → `invalid record Id: <id>`, exit 2.
3. `format = strings.ToLower(format)`; not `text`/`json` → exit 2.
4. Org: `--org` else `d.defaultOrg()`; empty or error → stderr `no org: pass --org <alias> or run: sf config set target-org=<alias>`, exit 2.
5. `tr, err := d.trace(org, id, refresh)`; err → stderr `why: <err>`, exit 1, stdout untouched.
6. Render: json → `json.MarshalIndent(tr, "", "  ")` + newline; text → `renderTraceText(tr)`.
7. For each `tr.Errors` → stderr `warning: <section>: <message>`. Exit 0.
